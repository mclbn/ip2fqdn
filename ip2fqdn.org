#+TITLE: ip2fqdn: reference document

* Goal and constraints
- Python command-line tool: from a list of IP addresses, possibly large, find the related FQDNs.
  Output: a CSV file with at least =ip,fqdn,source=.
- Works on internal networks and on Internet-facing assets. Fast (an aim, not a measured target: the
  quick methods should finish in minutes). Shodan and Onyphe API keys may be absent (their methods
  are off by default). A DNS server to query is sometimes available, sometimes not.
- Client: the organization whose network or assets are assessed; the operator runs the tool for it.
- Scope: the tool resolves IPs to names, nothing more. Features are suggested only when they
  serve that purpose; no side features (cost or credit reporting, usage estimates, API usage
  monitoring).
- Methods are the core of the tool: as many as reasonable, each enabled or disabled from the
  command line (no configuration file), with a sensible default set. Modular code is required:
  adding a method must be easy.
- Confidentiality: internal data (non-public addresses, names and domains learned from them)
  never reaches a third party: third-party services receive public addresses only (D24); DNS
  queries about internal data go only to servers the operator names (D19); the one exception is
  a transfer request for a zone the operator names with =--zones=, which also goes to that
  zone's own name servers and carries only the zone name (D21).
- Self-contained: no import from =pentest-tools= or any other private code (what is reused is
  copied into the project); any public PyPI package may be used (D4 lists the current ones).
- Separate from =pentest-tools= (=/work/pentest-tools.org=): this tool sends traffic to targets
  and to third parties, which that toolbox forbids. Only the operator runs it against real
  targets and third-party services, from a machine with network access; the coding agent runs
  it only in tests, against fake servers on the loopback interface.

* Environment
- Operator's machine: full Internet access when installing and preparing the environment.
- At run time on internal networks, Internet and cloud services may be unreachable: the tool
  must work with no Internet, using only what the network offers.
- Assumed until corrected: Linux, on the operator's own machine (no jump hosts).
- The operator uses mise for tool versions; uv is acceptable. mise may install uv itself
  (=uv = "latest"= under =[tools]=); the project does not depend on mise.

* Working method
- Principle (same as =pentest-tools=): a simple, robust and extensible tool beats one with many
  rarely used features. Smallest useful shape first; extras go to the backlog until a real need
  shows up. Robustness (damaged, hostile, very large input; bounded memory) is never optional.
- Steps:
  1. Design questions, one at a time.
  2. Shape restated: the agent restates the settled design in the conversation, its own
     fill-ins listed apart; the user validates it before any code, and the validated fill-ins
     are written into this document.
  3. Sources read first (API documentation, protocol specifications, source code of the
     programs writing a format): each one a module relies on is read and listed under Sources
     with the date checked. Open lists (Exchange paths for =http-ntlm=, service records for
     =dns-enum=, =placeholder= names) are fixed from them, written here, reviewed at step 6.
  4. Tests, then the tool.
  5. Checks: tests pass, =ruff= clean.
  6. Implementation review: what was decided while coding is listed in this document, for the
     user's approval.
  7. Delivery: usage notes in =README.md= and this document updated; then the
     operator runs it on real data and shares the results.
- Process details not listed here are decided when they come up: the agent settles minor ones and
  records them here, and asks the user about those that are hard to undo or change the direction of
  the work. The agent writes all the code (core, method modules, tests) itself, in sequence; no
  sub-agents (budget constraint).
- Steps 4 to 7 run in one session without stopping for questions: choices made while coding are
  taken by the agent and recorded in this document (step 6); they are presented to the user at
  the end of the session, after delivery.

* Decisions
- D1, settled: separate project in =/work/ip2fqdn/= on the development machine, with this document
  at its root (=ip2fqdn.org=, so the git repository carries it). The conventions of =pentest-tools=
  reused are only those this document states: uv project (D4), times in the local zone with offset
  (D26), debug masking (D28), XML entity declarations refused and control characters escaped (D26,
  Sources), test guard (D29). Rejected: a new tool inside =pentest-tools= (would break its
  no-network, no-target and standard-library-only rules, and its test guard).
- D2, settled: the operator runs the tool from a machine with network access.
- D3, settled: no external programs (nmap, dnsx, tlsx...); Python code only: libraries where
  they fit, own code otherwise.
- D4, settled: a uv project like =pentest-tools=: =pyproject.toml=, locked dependencies, Python 3.14
  from uv only (=python-preference = "only-managed"= in =pyproject.toml=: in the step-3 experiments
  uv fell back to the system Python, and uv's own build is the one tested with TLS 1.0 servers,
  Sources); =uv sync= downloads it into uv's shared folder (=~/.local/share/uv/python=). Install,
  once with Internet, offline afterwards (README): =uv sync --locked=, then =uv run python -m
  ip2fqdn.ranges= (D25); the =ip2fqdn= command is declared in =pyproject.toml= (D30). Rejected at
  step 6: the =setup.sh= of =pentest-tools= (it also kept Python inside the project folder; two
  README commands do the same job), and a shell launcher that finds =.venv/= next to itself (not the
  standard Python way). Code layout in D15 (the initial "one =.py= file" was replaced by a package).
  Dependencies: any public PyPI package. Current: =dnspython= (queries to a chosen DNS server, PTR,
  DNS message parsing), =cryptography= (certificate parsing); tests: =pytest=, =hypothesis=; lint:
  =ruff=. NTLM parsing and API calls with the standard library. Rejected: one file with inline
  dependencies run by =uv run= (offline runs depend on uv's cache); one standard-library-only file
  (own DNS client and certificate parser to write and harden against hostile servers). No
  =mise.toml= in the project.
- D5, settled: scale. Common lists: 100 to a few thousand IPs (several /24); rare maximum about
  10,000. All results fit in memory (a few MB). Third-party services are the slow part: about 1 IP/s
  for Shodan and Onyphe (10,000 IPs: about 2 h 45), down to 500 IPs a day for some free ones (D24);
  the API answer cache (D27) spreads them over days. Methods that query the IP should finish in
  minutes. Acceptable run times not stated by the operator.
- D6, settled: every source (methods that query the IP, DNS, nmap files, third-party) is a method
  module switched on or off from the command line. Default rule: a method is on by default when it
  works across routers, needs no credential, API key or third party, and returns a name for the host
  itself.
- D7, settled: methods that query the IP. Module names reviewed at step 6 and kept.
  | Module      | Sends                                                  | State     |
  |-------------+--------------------------------------------------------+-----------|
  | =tls=       | TLS without SNI on 443, 8443, 9443, 636, 465, 993,     | on        |
  |             | 995, 5986: certificate CN and SAN                      |           |
  | =rdp=       | 3389: RDP greeting, then TLS; certificate name; with   | on        |
  |             | NLA, first NTLM step inside CredSSP (D59)              |           |
  | =smb=       | 445: SMB2 and first NTLM step, never completed;        | on        |
  |             | DNS name, DNS domain, NetBIOS name                     |           |
  | =ldap=      | 389, 3268: anonymous rootDSE search; =dnsHostName=,    | on        |
  |             | domains (D58)                                          |           |
  | =mssql=     | 1433: TDS pre-login, then a Windows-authentication     | on        |
  |             | login stopped at the NTLM challenge (D63)              |           |
  | =netbios=   | UDP 137 node status: computer name, domain, MAC        | on        |
  | =smtp=      | 25, 587: greeting, EHLO, STARTTLS certificate; first   | on        |
  |             | NTLM step if offered (D60)                             |           |
  | =imap=      | 143, 993: STARTTLS certificate; first NTLM step if     | on        |
  |             | offered (D60)                                          |           |
  | =pop3=      | 110, 995: STLS certificate; first NTLM step if         | on        |
  |             | offered (D60)                                          |           |
  | =ftp=       | 21: host name in the greeting, AUTH TLS certificate    | on        |
  |             | (D61)                                                  |           |
  | =http=      | 80, 8080: =GET /=, host name in a redirect             | on        |
  | =http-ntlm= | first NTLM step on 5985 and 5986 =/wsman=, and         | on        |
  |             | Exchange paths on 443 (=/EWS/=, =/Autodiscover/=...)   |           |
  | =mdns=      | UDP 5353 reverse query to every IP: =host.local=;      | off       |
  |             | only hosts on the operator's own segment answer        |           |
  | =llmnr=     | UDP 5355 reverse query by multicast, IPv4; only        | off       |
  |             | hosts on the operator's own segment answer (D62)       |           |
  | =snmp=      | UDP 161: =sysName= with community =public=, then each  | on        |
  |             | =--snmp-community= (D64)                               |           |
  Module behavior: =smb= speaks SMB2/3 only (dialects 2.0.2 to 3.1.1); SMB1-only hosts give nothing
  (SMB1 to the backlog). NTLM steps (=smb=, =http-ntlm=): DNS domain and forest names feed zone
  learning (D20); rows per finding in D26. =smtp=: EHLO with the local address of the connection in
  brackets (=EHLO [10.1.2.3]=, =EHLO [IPv6:2001:db8::1]=); the name is the first word after the
  reply code (RFC 5321 section 4.3.1), in the greeting and in the first EHLO line; STARTTLS when
  offered, then EHLO again; first NTLM step when an EHLO lists it (D60); =QUIT=. =http= and
  =http-ntlm=: TLS on 443, 8443, 5986 and ports nmap reports as TLS, plain HTTP elsewhere; Host
  header = the IP; User-Agent =Mozilla/5.0 (compatible; ip2fqdn)=. =http= keeps the host of a 3xx
  =Location= when it is a name. =http-ntlm= (default ports 5985, 5986 and 443): =/wsman= only on
  5985 and 5986; on any other port, TLS or plain, the paths =/EWS/=,
  =/Autodiscover/Autodiscover.xml=, =/mapi/=, =/OAB/=, =/Rpc/= and last =/=, tried in that order
  (grounded in Exchange's default virtual-directory authentication, checked 2026-11-24; =/owa/=,
  =/ecp/=, =/Microsoft-Server-ActiveSync/=, =/PowerShell/= left out: forms, Basic or Kerberos by
  default, so no NTLM challenge); it stops at the first path that returns a challenge on a port.
  Certificate names (=tls=, =rdp=, =smtp= after STARTTLS, =sni=): read with =cryptography=, taking
  whatever it can read: the CN when the SAN extension fails, the SAN names when the subject fails; a
  certificate that does not load gives no name and is counted per method in the stderr summary
  (=certificates unreadable: N=). Rejected for now: an own DER reader as fallback (one more
  hostile-input parser for a case of unknown frequency; backlog until live runs show the count
  matters). Added at step 6 (operator, 2026-11-27): =ldap=, =mssql=, =imap=, =pop3=, =ftp=, =llmnr=,
  and the first NTLM step in =rdp= (the backlog's =rdp-ntlm=) and =smtp= (D58 to D63). Then =snmp=
  (operator, 2026-11-27, D64). Backlog: =dns-chaos= (=hostname.bind=, =id.server=: little gain, the
  DNS servers it would name already get names from =smb=, =ptr= or certificates). Rejected: =ssh=,
  =vnc= and other services whose banners hold no names. Estimate, not measured: about 28 connection
  attempts per IP with the default methods (19 before D58 to D64); 5,000 IPs with 500 in parallel
  and the 3 s connect timeout (D17) take about 14 minutes in the worst case.
- D8, settled: nmap XML scan results (and masscan XML, D28) accepted as input, several files
  at once (=scans/*.xml= expanded by the shell). Parsing code from =pentest-tools= (its
  =nmap_report= tool) copied into the project, never imported, and extended: its parser drops
  the =scaninfo= scanned ranges, which D9 needs (the =extraports= port lists are not needed,
  D9); format notes copied under Sources.
- D9, settled: port selection.
  - Without nmap input: each module probes its default ports; an option adds or replaces
    ports (syntax in D13). Default lists stay short: each extra default port costs one
    attempt per IP.
  - With nmap input: a port is skipped when the scan covered it (scanned ranges in =scaninfo=), the
    host has port results (a =<ports>= element) and the port is not listed =open= or
    =open|filtered=. nmap accounts for every scanned port, either listed or counted in
    =<extraports>=, so such a port was found closed or filtered; the =extraports= port lists are not
    read. A host without port results (ping scan, host timeout) has its ports probed as usual.
    =open= and =open|filtered= ports are probed, and ports outside the scanned ranges are probed as
    usual (for example UDP 137 after a TCP-only scan). With =-sV=, each module also takes open ports
    whose nmap service name is in its declared =nmap_services= list (=http= on 8000, =smtp= on
    2525); ports nmap reports as TLS-wrapped also go to =tls=. =tls= also tries every open TCP port
    that no selected module takes (by default port, option or service name), so HTTPS on any port is
    found without relying on service names. Several files holding one host are merged: its open
    ports and scanned ranges are the union over the files that hold it; it counts as down only if
    every file that holds it reports it down. Hosts reported down are skipped by methods that query
    the IP; DNS and third-party methods still run for them.
  - Rejected: probing only open ports (a TCP-only scan would silently disable =netbios=);
    nmap files as a plain IP list (misses non-standard ports).
- D10, settled: input types: IPs and CIDR ranges on the command line; IP list files, or =-= for
  stdin; nmap or masscan XML files; host names (D55). DNS zone files: backlog (D25).
- D11, settled: input syntax. Every plain argument is an input, its type recognized: an IP or CIDR
  range is a target; =-= reads an IP list from stdin; anything else is a file when it exists
  (otherwise a host name, D55), read as nmap or masscan XML when its first 4 KB hold =<!DOCTYPE
  nmaprun= or =<nmaprun= (nmap writes the DOCTYPE right after the XML declaration, then a comment
  holding its full command line, which can push =<nmaprun= itself past 4 KB; masscan writes
  =<nmaprun= without a DOCTYPE), otherwise as an IP list. A CIDR range expands to every address it
  contains, network and broadcast addresses included (like nmap), IPv6 too. Any mix and shell
  patterns work: =ip2fqdn scans/*.xml extra.txt 10.9.9.9=. Stderr states how each file was read
  (=scans/a.xml: nmap XML, 254 hosts=). A file named like an IP is forced with =./10.0.0.1=. Input
  errors stop the run before any traffic, exit 2: an argument that is neither an IP, a CIDR range,
  an existing file nor a host name ("not an IP, CIDR range or host name, and no such file");
  unreadable file; file over 64 MB that is not nmap or masscan XML. Damaged XML keeps its complete
  hosts, with a warning. Rejected: nmap-style =-iL= and =--nmap FILE...= (=--nmap= swallows later
  targets); options for every input type (=-t=, =-i=, =--nmap=).
- D12, settled: method selection. =-m LIST= says what runs (default: the =default= preset);
  =--skip LIST= removes methods from it. Lists mix method names and preset names:
  =ip2fqdn -m default,mdns --skip netbios 10.0.1.0/24=. Rejected: one option with =+=/=-=
  signs (the option parser reads =-m -netbios= as two options); one flag per method.
- D13, settled with D12 (option names reviewed at step 6): =--list-methods= prints one line per
  method: name, on/off state, kind, phase, presets, needs (API key variable, DNS server) and ports.
  Options: =-m/--methods=, =--skip=, =-o/--output=, =--dns-server=, =--protected-dns= (D19),
  =--zones=, =--no-forward-confirm= (D19), =--parallel=, =--connect-timeout=, =--timeout=,
  =--max-ips=, =--max-zones=, =--debug=, =--list-methods=, =--version=, =--shodan-search=,
  =--snmp-community= (D64); generated for every module: =--<method>-timeout= and, for every method
  that probes ports of the listed IPs (=smb=, =netbios=, =rdp=, =mdns= included; not =sni=, which
  uses the ports where =tls= answered), =--<method>-ports= (the test fakes need ports 1024 and
  above, D29). Per-module options are prefixed with the module name and grouped by module in
  =--help= (=--tls-ports=, =--smtp-ports=...); a list may include the word =default= (=--tls-ports
  default,10443= adds, =--tls-ports 10443= replaces). API keys only from environment variables
  (listed in D24), never from the command line; SNMP communities are the exception, given with
  =--snmp-community= at the operator's request (D64). API base addresses can be overridden with
  =IP2FQDN_<METHOD>_URL= variables (not shown in =--help=; for the test fakes). A method named
  explicitly whose key is missing stops the run before any traffic, exit 2; the same method pulled
  in by a preset is skipped with a note on stderr. Renamed at step 6: =--paranoid= became
  =--protected-dns= (in nmap, "paranoid" is the slowest timing mode) and =--no-confirm= became
  =--no-forward-confirm= (elsewhere "no confirm" means "do not ask before acting"); both new names
  match the terms of the README and the stderr notes.

- D15, settled: code layout. A package with an explicit list of methods:
  : /work/ip2fqdn/
  :   ip2fqdn/
  :     cli.py inputs.py nmapxml.py runner.py output.py
  :     ranges.py                               shared-range download (D25)
  :     data/shared-ranges.txt                  written by ranges.py
  :     proto/ntlm.py proto/tls.py              shared protocol code
  :     methods/__init__.py                     METHODS = [tls, rdp, smb, netbios, ...]
  :     methods/tls.py methods/smb.py methods/netbios.py ...
  :   tests/
  :   pyproject.toml uv.lock README.md LIVE-TESTS.md ip2fqdn.org
  The =ip2fqdn= command is an entry point declared in =pyproject.toml= (D30). Adding a method:
  one file in =methods/=, one line in =METHODS=, its tests. File names other than =methods/= and
  =proto/= are provisional.
  Rejected: one file (several thousand lines); automatic discovery of method files (what
  runs would depend on the files lying in the folder).
- D16, settled: concurrency and module contract.
  - asyncio: modules are =async def=; blocking libraries (=urllib=) run through
    =asyncio.to_thread=. Tests run with asyncio debug mode on, which reports any step holding
    the event loop longer than 100 ms (catches blocking calls).
  - The core reads inputs, applies port selection (D9), enforces limits (connections overall
    and per IP, per-method =parallel=, queries per DNS server, API pacing, timeouts; D17,
    D28), turns any error inside a module into a warning (a module never stops the run),
    passes third-party modules public addresses only (D24), collects findings and writes the
    output.
  - API pacing is done by the core only, from the delay each module declares in =rate=: the time
    between two requests, set from the service's strictest documented limit shorter than a day
    (urlscan: 100/h, so one request every 36 s; mnemonic: one every 6 s; VirusTotal: one every 15 s;
    OTX: 1,000/h; Shodan and Onyphe: 1/s). Daily limits are not counted: the service's own
    quota-spent reply stops the module for the run with a one-line note; its answers stay in the
    cache (D27). Quota-spent replies: any HTTP 429 asking for a wait of more than an hour, from any
    service (urlscan gives its reset time); mnemonic's HTTP 402; VirusTotal's HTTP 429
    =QuotaExceededError= still returned after a 60 s wait (the same code covers its minute and daily
    quotas; wait and retry details in D45). An HTTP 429 asking for a wait of an hour or less is
    waited out; without =Retry-After=, waits of 5, 10 then 20 s. InternetDB: declared at 5
    requests/s, halved on each HTTP 429, never sped up (its documented limit, bursts of up to 10,000
    requests/s, is far higher, but the service is free and shared and its HTTP 429 behavior is
    undocumented). Rejected: several windows per service with daily counters (a run cannot see the
    quota used by earlier runs, so its count is wrong).
  - Work order for methods called per IP and port (=lookup=): tasks are queued by method, then port,
    then IP; each free connection slot takes the next task, so a sweep may start before the previous
    one ends. DNS and third-party modules run alongside (D24, D27).
  - Read limits: 64 KB of HTTP headers; per SMTP session at most 100 lines of at most 4 KB each
    (over the limit, the session ends with a warning and names already read are kept); 64 KB
    per SMB, NetBIOS or mDNS reply, 32 MB per API response (over the limit, the reply is
    dropped with a warning).
  - A module declares =name=, =help=, =kind= (=active=, =dns=, =file=, =api=), =presets=,
    default =ports=, =nmap_services= (nmap service names it takes, D9), =rate= (delay between
    API requests), =timeout= (when longer than the default, D17), =phase= (1 or 2), optionally
    =parallel= (cap on its simultaneous calls); implements =lookup(ip, port, ctx)= (once per IP
    and port, yields findings) or =lookup_all(ips, ctx)= (whole list at once: bulk APIs, zone
    transfers, nmap names); phase-2 methods read the names found and the TLS ports
    that answered from =ctx=; optionally =add_arguments()= (own options) and =check()= (key
    present, before any traffic).
  - Rejected: threads (a library call ignoring its timeout holds a thread forever; 8 MB of
    virtual memory reserved per thread by default); mixing async and plain modules.
- D17, settled: timeouts.
  - =--connect-timeout S= (default 3): TCP connection, or any reply to a UDP packet; what a
    dead host or filtered port costs.
  - =--timeout S= (default 10): total time one module gets for one IP and port; enforced by
    the core by cancelling the call, so no module can hang. Modules may declare a longer
    default (=smtp=: 20, for deliberately delayed greetings), which replaces the built-in 10 s;
    an explicit =--timeout= applies to every module.
  - =--<module>-timeout S=: per-module override, generated by the core for every module; it
    wins over both.
  - Retries: none for TCP (a retry doubles the cost of dead hosts); one for UDP.
  - DNS: 2 s per attempt, 2 attempts per query; a server with 20 queries in a row unanswered
    after both attempts is dropped for the run, with a warning.
  - Third-party APIs: 10 s to connect, 30 s to read per request; on HTTP 429 or 5xx, wait
    (=Retry-After= if given, otherwise 5, 10 then 20 s) and retry up to 3 times, each wait
    using one retry; after 5 requests in a row still failing once their retries are used up,
    the method is switched off for the run, with a warning. Quota-spent replies: D16.
  - Whole-list methods: no total limit; a connection (zone transfer, bulk download) that
    receives no data for 60 s is abandoned. Pacing delays and HTTP 429 waits are not idle time.
  - Blocking libraries in threads must pass their own timeouts (threads cannot be cancelled).
  - Stderr summary counts timeouts per method.
  - Rejected: a single =--timeout= (cannot make dead hosts cheap and slow services tolerated
    at once). Backlog: speed profiles like nmap's =-T=; a dead-host shortcut.
  - Estimate, not measured: 10,000 dead IPs, 19 attempts each, 3 s, 500 in parallel: about
    19 minutes. With nmap input, hosts reported down are skipped.
- D18, settled (principle; per-service details in D24): third-party modules minimize
  requests and credits. They use =lookup_all= to plan requests: batch or range queries when
  the service offers them, per-IP lookups otherwise, the choice depending on how dense the IPs
  are in a range; the same IP is never asked twice in one run.
- D19, settled: DNS basics.
  - =ptr=: reverse DNS for every IP, every PTR record kept. On by default (=default=, =dns=,
    =passive=).
  - Servers: =--dns-server IP[:PORT][,...]= (port 53 unless given; an IPv6 server with a port
    in brackets, =[::1]:5353=) if given, otherwise the
    =nameserver= lines of =/etc/resolv.conf= (normal mode; see the protected rule below). Every

- D64, settled (operator, 2026-11-27): =snmp= (=default=, =active=; UDP 161, nmap service =snmp=).
  Community =public= first, then each =--snmp-community NAME= (repeatable, 1 to 255 bytes, repeats
  dropped) in command-line order, until one answers. Each community gets one round: a GetRequest for
  =sysName.0= (1.3.6.1.2.1.1.5.0, RFC 3418) sent as SNMPv2c (RFC 1901, 3416) and as SNMPv1 (RFC
  1157) together, then the connect timeout; no retry, so a silent IP takes the connect timeout once
  per community (=public= and two more fit in the default 10 s). A device that accepts =public=
  never receives the operator's communities. Rows: the sysName (nulls and spaces trimmed), detail
  =161 SNMP sysName (public)= or =(community N)=, N its rank among the added communities: a
  community's value never reaches the CSV or the debug lines. A closed port (ICMP port unreachable)
  ends the IP at once; a v2c exception (=noSuchObject=...) or an error status gives no row. Two
  rules give way at the operator's request: the tool sends credentials to the listed hosts (Out of
  scope), and they come from the command line rather than the environment (D13), so they show in the

** Methods that query the IP (traffic to the target)
- TLS certificate without SNI (the server sends its default certificate): CN and SAN names.
  Ports: 443, 8443, 636 (LDAPS), 3389 (RDP: Windows puts the machine FQDN in its certificate;
  RDP needs its own negotiation before TLS, so 3389 is not a plain TLS port — the =rdp=
  module does the exchange first, D7), 5986 (WinRM), 993, 995, 465.
- NTLM challenge over SMB 445, RDP, HTTP, WinRM, MSSQL: machine DNS name and AD domain, before
  any login. Strong on internal Windows networks.
- Banners: SMTP greeting (=220 mail.example.com ESMTP=), HTTP redirects.
- LDAP rootDSE on domain controllers, anonymous: =dnsHostName=.
- NetBIOS node status (NBT-NS, as =nmblookup -A=): one unicast UDP packet to port 137 of the
  host; returns its NetBIOS name table (computer name, workgroup or domain) and MAC address.
  Short names, not FQDNs. Works across routers when UDP 137 is not filtered (RFC 1002).
- mDNS unicast query to UDP 5353 of the host: =host.local= names (Apple, Linux, printers).
  Responders should ignore queries from outside their subnet (RFC 6762, section 5.5), so it
  works on the operator's own segment only.
- Host names in IMAP, POP3 and FTP greetings (checked 2026-11-27). nmap's
  =nmap-service-probes= (github.com/nmap/nmap, master): rules that capture a host name (=h/=
  field): IMAP 72 of 172, POP3 135 of 264, FTP 138 of 778. Position of the name in those rules:
  first word after the reply code (IMAP 36, POP3 54, FTP 93), APOP stamp =<...@host>= (POP3 41,
  FTP 1), elsewhere (IMAP 36, POP3 40, FTP 44). Default greetings without a name: Dovecot
  (=Dovecot ready.=), Courier IMAP, Exchange 2007 and later (=The Microsoft Exchange IMAP4 service
  is ready.=, default of =Set-ImapSettings -Banner= and =Set-PopSettings -Banner=,
  learn.microsoft.com), vsftpd, Pure-FTPd, FileZilla Server, Microsoft FTP, Serv-U. Names by
  default: Exchange 2000 and 2003 (=(host)=), Cyrus, Zimbra, MDaemon, hMailServer, CommuniGate,
  POP3 APOP stamps (Courier, Kerio, Qpopper, GNU); FTP servers of printers (Lexmark, Dell, Epson,
  Konica Minolta, Kyocera, IBM Infoprint), MikroTik, Synology, Cisco IronPort and Aironet, and
  BSD, Solaris, HP-UX and GNU inetutils ftpd, nearly all as =220 HOST ... FTP server ... ready=.

** DNS (no traffic to the target)
- Reverse DNS (PTR record): 0 or more names (usually 0 or 1), often missing or generic
  (=1-2-3-4.dsl.isp.net=). Internal only through an internal DNS server.
- Forward confirmation: resolve each name found and check it points back to the IP (one DNS
  query per name); separates current names from stale ones.
- Zone transfer (AXFR) from an internal DNS server, when allowed: A/AAAA records inverted.
- DNS zones from a provider (Route 53, Cloudflare, Azure), exported zone files, IPAM or DHCP
  exports: inverted the same way.
- With credentials: AD computer objects (=dNSHostName=), AD-integrated DNS zones, SNMP
  =sysName=.

** nmap and masscan XML (copied from =pentest-tools=, sources checked 2026-10-30)
- Sources: =nmap.dtd= (nmap master, last changed 2022-06-28); nmap's =xml.cc= (escaping) and
  =service_scan.cc= (fingerprints); masscan's =src/out-xml.c= and =src/output.c= (last changed
  2026-04-18). Code to copy: the parsing part of =/work/pentest-tools/nmap_report.py=.
- nmap escapes =--= as =-&#45;=, and every byte below 0x20 or above 0x7F as =&#xNN;=. Control
  characters thus become references that XML forbids (=&#x1b;=); rewrite them as =\x1b= before
  parsing. Non-ASCII text arrives byte by byte (=Ã©=); decode it again as UTF-8 when valid.
- masscan: one =<host>= per port or banner, banners escaped as =\xNN=, no =exit= attribute in
  the end record, =\r\n= line endings.
- Hostile input: XML entity declarations refused. Incomplete or damaged files keep their
  complete hosts. Script =<script>= output is escaped as literal =\xNN= text, not XML
  references: smb-os-discovery names can end in a literal =\x00=, stripped before the
  host-name check. Hosts from =-Pn= and =-sL= scans are never reported down. In a =-sU= scan,
  ports outside the port list can come back =open|filtered=.

** Python building blocks (checked 2026-11-24)
- =ssl= (Python 3.14.7, OpenSSL 3.6.5, local test): with =CERT_NONE=,
  =minimum_version=TLSv1=, =set_ciphers("DEFAULT:@SECLEVEL=0")= and no =server_hostname= (no
  SNI), a TLS 1.0-only server answers and =getpeercert(binary_form=True)= returns the DER
  certificate. Distribution OpenSSL builds with crypto policies not tested.
- asyncio and =ssl= on uv's managed Python 3.14.7 (the one =uv sync= installs; it bundles
  OpenSSL 3.5.9, not the system's 3.6.5), loopback only, 2026-11-24; script and output in
  =/work/ip2fqdn-sources/exp-asyncio/=:
  - No SNI: =asyncio.open_connection(ip, port, ssl=ctx)= sends no SNI when the host is an IPv4
    or IPv6 address, nor with =server_hostname= =None= or =""=; with a name, the name is sent
    (seen by the server's =sni_callback=). The DER certificate comes from
    =writer.get_extra_info("ssl_object").getpeercert(binary_form=True)=; the =peercert= extra
    is ={}= with =CERT_NONE=.
  - TLS 1.0-only server: reached with =minimum_version = TLSVersion.MINIMUM_SUPPORTED= and
    =set_ciphers("DEFAULT:@SECLEVEL=0")= (TLSv1, ECDHE-ECDSA-AES256-SHA); default settings
    fail (connection reset). =TLSVersion.TLSv1= raises a =DeprecationWarning= in 3.14,
    =MINIMUM_SUPPORTED= does not.
  - =StreamWriter.start_tls(ctx)= after a plain exchange works, without SNI. Around such a
    connection's close, asyncio's own logger once wrote "returning true from eof_received()
    has no effect when using ssl", which logging prints on stderr by default.
  - UDP to a closed port: a connected datagram endpoint (=remote_addr=) gets
    =error_received(ConnectionRefusedError)= for each datagram (IPv4 and IPv6); an
    unconnected one gets nothing. TCP to a closed port: =ConnectionRefusedError= at once.
  - Debug mode: =asyncio.run(..., debug=True)= logs a warning on the =asyncio= logger
    ("Executing <Task ...> took 0.151 seconds") for a 150 ms blocking step, none for 50 ms; a
    =logging.Handler= on that logger catches it.
  - =asyncio.wait_for(asyncio.to_thread(...), 0.3)= returns after 0.3 s, but the thread runs
    on and =asyncio.run= waits for it before returning: a blocking call delays the exit up to
    its own timeout.
  - =RLIMIT_NOFILE=: the soft limit can be raised up to the hard limit (524288 here) without
    privileges; above it, =ValueError=.
- =dnspython= 2.9.2 (2026-11-03, ISC, Python >= 3.11): async resolver =dns.asyncresolver=.
  Found at step 3: its =Resolver= fails over to the next server instead of asking every
  server (D19 builds one resolver per server); its zone-transfer loop has no size limit and
  held the event loop up to 0.8 s (the transfer loop is hand-written, D20). Zone files:
  saved =dig axfr= output is parsed only when the zone name is given; a CNAME beside other
  data at one name makes dnspython reject the whole file; =from_file= allows =$INCLUDE= by
  default; =$GENERATE= has no size limit; parsing ran at about 21,000 records/s (why
  =zonefile=, in the backlog, should use its own lenient reader, D25).
- =cryptography= 50.0.2 (2026-09-30, Apache-2.0 or BSD-3-Clause): X.509 SAN parsing. It
  rejects some real certificates: some fail at load (wildcard CN as PrintableString, BER),
  others at =.subject= or =.extensions= (T61String, one malformed extension); handling in D7.
- =impacket= 0.13.1 (2026-05-19, modified Apache licence): NTLM host info over SMB without
  credentials (=getServerDNSHostName()=, =getServerDNSDomainName()= after an anonymous login
  attempt). Large library.

** Prior art (not used, see D3; shows how others solve the same problems)
- No maintained tool combines these sources. hakip2host (PTR plus certificate names) has no
  licence and no change since 2022-04.
- dnsx (MIT, Go): PTR for an IP list, resolver list, 100 threads by default, JSONL.
- tlsx (MIT, Go): CN/SAN on several ports, 300 connections by default, falls back to other TLS
  stacks for old servers.
- nmap: =-sL= does reverse DNS without sending packets to targets (=--dns-servers= picks the
  servers); scripts =ssl-cert=, =rdp-ntlm-info=, =smb-os-discovery=, =*-ntlm-info=.
- NetExec (BSD-2-Clause, Python): SMB and RDP name and domain without credentials, via impacket.
- massdns (GPL-3.0, C): PTR at 10,000 concurrent lookups by default.
